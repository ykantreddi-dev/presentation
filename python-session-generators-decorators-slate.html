Generators?

Produce values only when asked

Concept

What is a generator?

One value at a time

It gives you the next value only when you ask for it, instead of building a full list first.

Pause and continue

yield pauses the function. Later, Python continues from the same line.

If a function has yield, calling it gives a generator object.

Code Walkthrough

First generator example

def countdown(n): # generator function while n > 0: yield n # give one value, then pause n -= 1 gen = countdown(3) # function body has not run yet next(gen) # 3 next(gen) # 2 next(gen) # 1 for value in countdown(3): print(value) # for-loop handles StopIteration automatically
yield gives and pauses
next() continues execution
for handles termination

Decorators?

Wrap behavior around existing functions

Why Decorators

Why decorators are useful

A decorator wraps a function and adds extra behavior around it.
  • 1Keep your main function simple while adding timing, logging, or checks outside it.
  • 2Reuse one decorator on many functions instead of repeating the same code.
  • 3Use @decorator syntax for readable intent at definition time.
Code Walkthrough

Simple decorator example

import time def timed(func): def wrapper(*args, **kwargs): start = time.perf_counter() result = func(*args, **kwargs) print("Time:", round(time.perf_counter() - start, 3), "seconds") return result return wrapper @timed # same as: process = timed(process) def process(items): return sum(items)
@name applies decorator
*args, **kwargs works for any input
Wrapper returns result
Built-ins

Beginner-safe built-in decorators

  • 1@property exposes computed attributes as fields.
  • 2@staticmethod / @classmethod help define method behavior in classes.
  • 3@functools.lru_cache stores previous results to speed up repeated calls.
@property @staticmethod @classmethod @lru_cache @wraps

Loops vs Generators

Same answer, very different memory profile

Comparison

Normal list loop vs generator loop

Both can give the same answer. The big difference is memory usage.

List style (store everything)
nums = [x * x for x in range(1_000_000)]
evens = [n for n in nums if n % 2 == 0]
total = sum(evens)
Generator style (stream values)
sum(n for n in (x * x for x in range(1_000_000)) if n % 2 == 0)

Values are computed on demand, so memory stays much smaller.

Memory Math

Memory difference in simple terms

High
List approach stores many values at once
Low
Generator approach keeps only current state
Same Output
Both produce the same final result
Key Trade-off generators save memory but you usually loop only once

Use lists when you need random access; use generators for streaming or huge datasets.

Decision Guide

When each approach is the better fit

Prefer Lists

You need indexing, slicing, sorting, length checks, or multiple passes over the same data.

Prefer Generators

You process sequentially, stream from I/O, or handle input too large to load at once.

Exceptions?

Fail gracefully and recover intentionally

Core Syntax

Basic try/except flow

def safe_divide(a, b): try: result = a / b except ZeroDivisionError: print("You cannot divide by zero") return None else: return result finally: print("Division attempt finished")
except catches known errors
else runs when no error happened
finally always executes
Best Practices

Exception tips for beginners

  • 1Catch specific exceptions like ValueError or FileNotFoundError.
  • 2Do not hide errors with a plain except:.
  • 3Show a clear message so users know what went wrong.
  • 4Use finally for cleanup code that must always run.
raise from exc finally CustomError logging

Good exception handling makes your programs easier to debug and trust.
